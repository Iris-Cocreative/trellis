# D43. One token source, in cells and points

## Context

A native screen and a web screen should share one seed. Cheap now, expensive after the first app pins a version.

## Options considered

One part was weighed: rem and px were set aside for cells and points, so no platform's unit is privileged.

Not weighed at the time. Options named since: keep the stylesheet as the source and generate native values from it; hand-kept token files per platform; an existing token pipeline in place of a small generator.

## Decision

`tokens.json`, in the W3C Design Tokens format, holds every shared value in cells and points, never rem or px. `tools/build-tokens.js` writes core's generated tokens and holds the rem conversion.

## Consequences

To change a shared value, change it in `tokens.json` and run the generator. `contract.js` fails on a stale `core.css` or a web unit in the file. Formula and web plumbing stay hand-written.
