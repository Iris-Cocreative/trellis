# D51. Keyboard reach: markup and runtime

## Context

A rail, a board and a wide code sample or table in prose scroll sideways. Chrome and Firefox let a keyboard reach a scroller with nothing focusable inside; Safari does not.

## Options considered

The markup contract alone (authors and renderers add the tab stop); the runtime for everything (`settle.js` adds it to any scroller, but cannot give it a label); or a split. The split was chosen.

## Decision

Rails and boards carry their tab stop in the markup contract: `tabindex="0"`, `role="group"` and a label, since only the author has the words. `settle.js` adds the tab stop to a `pre` or `table` in prose that overflows with nothing focusable inside, since content from an editor cannot carry it.

## Consequences

A test fails any sideways scroller with no way in. Carried by Keyboard reach for scrollers.
