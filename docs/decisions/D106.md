# D106. A prose gallery is images and nothing else

## Context

On the planning app's owed-cards bench, a paragraph inside `.prose` computed as `display: grid`. A chip naming a record (an inline-flex pill, a link) became a grid item and its sentence split into pieces; the same chip in a plain `.t-body` paragraph flowed.

The cause was not the settle path. It was the gallery rule: Markdown emits images on one line as one paragraph, so `.prose` lays a `figure` or a `p` out as a grid of squares when it holds two or more of them. The rule counted links as images (`:has(> :is(img, a) ~ :is(img, a))`), for a linked image. So any paragraph with two links in it was a gallery: two chips, and also two plain links in an ordinary sentence. The specimen's post had no paragraph with two links, and the alignment test reads a block's top, which a grid does not move.

## Options considered

Count a link only when it holds an image (`a:has(> img)`). That is the meaning, and `:has()` cannot be nested inside `:has()`.

Mark galleries in `settle.js`, which can see text nodes. Exact, and it puts a layout decision in the runtime in every browser for a case CSS can nearly decide.

Drop the paragraph gallery and keep the figure's. Markdown's own output for images on one line would fall back to inline images of any size.

Leave a classed element alone, an image included, as `.prose` leaves a classed `div` alone. A CMS classes its images (`wp-image-12`), and they are still images.

## Decision

- **An image counts alone or inside a link**, through relative selectors that end at the image: two images (`> img ~ img`), an image and a linked one (`> img` with `> a > img`), or two links the second of which holds an image, in a block where a link holds an image (`> a > img` with `> a ~ a > img`).
- **A paragraph is a gallery only when images are all it holds**: every child is an image that is not a face (`.avatar`), a link with no class, or a `br`. Any other element makes it text: a mark, a `span`, a tag, a button. A link with a class is a component, as a `div` with one is.
- A `figure` needs no such guard; its caption is where its words are.
- `tests/layout.js`, both engines: eleven shapes of paragraph and figure are text or a gallery as they should be; the specimen's sentence with a tag, two inline-flex chips and two links keeps every line of words a line height from the last and settles to whole cells.

## Consequences

Anything inline-level a product puts in a sentence stays inline. A chip for a record named in text can be an app's own part now; whether it becomes a primitive waits for a second app's shape.

Two cases CSS cannot tell apart remain galleries: a paragraph of nothing but bare words and two images, and a paragraph whose only children are a text link followed by a single linked image. Both are rare, and either is text again with the images in a `figure` or a mark around a word.

A paragraph that mixed images with a mark or a classed link was a gallery and is text now.
