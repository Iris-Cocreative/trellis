# D101. A link may be the current one

## Context

The community app's schedule switches its view (month, list) and its scope (a community, everything open) with links: each is a page of its own, so it can be shared and bookmarked. A link says it is the one you are on with `aria-current="page"`. A tab drew its selected look only for `aria-selected`, which belongs to a `role="tab"` in a tablist, and a tag drew solid only for `aria-pressed`, which belongs to a button. The shared state layer already took `aria-current` (its 10% wash), but not the mark that keeps selected from looking merely hovered.

## Decision

`.tab[aria-current]` draws as a selected tab (its ground and its line, or the raised face in `.cc-seg`), and `.tag[aria-current]` as a solid one, as `aria-selected` and `aria-pressed` do. `aria-current="false"` is not current. A tab or a tag that is a link has no underline, as a button that is a link has none. Markup: `nav.tabs > a.tab[aria-current="page"]`, `.cluster > a.tag[aria-current="page"]`. `tests/layout.js`, both engines.

## Consequences

Navigation that looks like tabs or chips needs no ARIA it doesn't mean.
