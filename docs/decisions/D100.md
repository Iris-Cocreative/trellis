# D100. A button's face: its family, weight, case and spacing

## Context

The community app's studio draws its buttons in Cormorant Garamond, bold, in capitals spaced .18em, while the rest of the ecosystem's buttons are Geist in sentence case. A scope could already set a button's letter spacing (`--btn-tracking`, read with no default, so it inherits), but not its family or its case: the button took the body's family and the control weight. The studio's forms kept their own `.btn` (the community app's ledger 19).

Letter spacing also follows the last letter, so a label spaced .18em sat off center by half that.

## Options considered

Class variables only (`--btn-font`, `--btn-case`), set in a context. A community is a scope, and a scope is a product: it turns knobs, and a context's variable is for a one-off.

Knobs for every control at once (buttons, tags, tabs, bar links). The studio asks for buttons alone, and tags already have `--tag-case` and `--tag-tracking`.

## Decision

- Four knobs, as the tag has two: `--font-button` (follows `--font-sans`) and `--fw-button` (follows `--fw-label`), unset in core so they follow on every scope (D96); `--button-case` (`none`) and `--button-tracking` (`0`).
- `--btn-tracking` stays, for a context's one-off, and wins over the knob.
- A button indents its text by its letter spacing, so the space after the last letter is matched before the first and a spaced label stays centered. Padding is unchanged, and so is any button with no spacing.
- `tests/layout.js`, both engines: the four knobs reach a button, a spaced label is centered, padding stays even.

## Consequences

A community can carry its own button face as a scope. Tags, tabs and bar links keep theirs; a product that wants them to match sets their knobs too.
