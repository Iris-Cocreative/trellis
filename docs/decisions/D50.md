# D50. The knowledge base lives in the repository

## Context

The chapters need stable IDs that tests, the changelog and commit messages can cite.

## Options considered

Markdown pages in `docs/` in the public repository; documents in the plan, which are private and can name people but cannot be cited by link from the code; or drafts in the plan moved into the repository after approval. `docs/` was chosen.

## Decision

The knowledge base is Markdown in `docs/`, one folder per chapter, one page per rule, decision or part.

## Consequences

It is public, so a decision's "who" is a role, never a name. A page describes its subject as it is in that commit.

2026-11-12

## Who

The owner.
