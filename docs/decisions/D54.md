# D54. A relational palette

## Context

Every color role was a fixed light and dark pair that a product set by hand, fourteen of them plus five kinds and three statuses. Nothing related one to another, so a product could break legibility without noticing: ink on the accent was white in both themes, about 2.5:1 on the dark theme's light blue, which fails WCAG AA. Core already had relational recipes (tag fills and edges, the avatar wash, the scrollbar, the skeleton, the scrim) built with `color-mix()`.

## Options considered

Weighed at the time, on a decision card in the plan:

- Fix the ink only: white in light, an 18% mix of the accent into black in dark, with the primary hover moving toward the ink. Visual, no change to the token source's shape.
- The ink fix plus a Color section in the specimen showing roles as light and dark pairs and every recipe as "a role, or a mix of a role". No framework change beyond the fix.
- A relational palette: seeds, with every role derived through relative colors, ink computed per fill and gradient tokens from base colors in a named interpolation space. Breaking: the token source's shape and every product's palette knobs change.

The third was chosen, now, before the first app pins a version.

## Decision

A product sets seeds and never a role. The neutral seed gives the neutral roles their hue and chroma, each at a lightness for each theme (a ladder in `tokens.json`). Every other seed is a hue, in its light-theme form; the dark theme lifts it by `--color-lift`. Ink on the accent flips at `--ink-flip`: white below it, a dark ink of the accent's own hue above it. Gradients are an interpolation space and stops (`--gradient-accent`, `--gradient-surface`), so any direction or shape can use them. `math.js` derives the same roles in arithmetic.

The card named `contrast-color()` where supported, with the computed ink as a fallback. The build uses the computed ink everywhere, because `contrast-color()` picks pure black or white by an algorithm that is not yet pinned down, so the two engines could draw different inks; one formula draws the same ink in both.

## Consequences

- Breaking: a product layer that set role colors sets seeds instead. Both example layers are seeds only.
- `tests/contract.js` checks contrast for core and every product layer, in both themes, so a seed that makes text unreadable fails the contract.
- A role derives from the root's seeds, so a context that changes a seed on an inner box does not recolor it.
- A browser without relative colors gets core's palette as fixed colors, resolved by `math.js`.
- The specimen's Color section shows the seeds, the roles and the mixes.
