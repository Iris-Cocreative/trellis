# D110. Beside Tailwind: the layer statement, and three class names Tailwind must not make

## Context

The first app is built on Tailwind v4 (4.3.2, through `@tailwindcss/postcss`, with `tw-animate-css` and shadcn's token names) and means to move to Trellis one surface at a time, so for a while both load on every page. Since D21 put every layer under one namespace, the README has asked for `@layer theme, base, trellis, components, utilities;` before either stylesheet, and `tests/layers.js` has proved that order, but only against a stand-in with the shape of Tailwind's layers. Nobody had run Trellis beside Tailwind itself, built the way an app builds it.

The spike (`experiments/tailwind/`) builds an app stylesheet shaped like the first app's with the real Tailwind, once as `next dev` would and once, with `core.css` imported from the same entry, as a production build would (Lightning CSS minifies and lowers it). Its page holds Trellis alone, Trellis cards in a layout made of Tailwind utilities, and a utility on a Trellis element, and loads the stylesheets in seven orders. `tests/tailwind.js` compares each with Trellis alone, in Chromium and WebKit, with core's defaults and with the first app's product layer.

What it found:

- **The statement holds against real Tailwind.** With it, Tailwind first, Trellis first or one bundle: every box on the Trellis surface sits exactly where it does with no Tailwind (39 of 39), a margin utility beats the reset, the type roles beat preflight, and `align.js` passes the page (0 off in 12 runs with the first app's layer). Tailwind's build keeps the statement first; Lightning CSS rewrites it as `@layer trellis;` between `base` and `components`, which is the same order, and leaves `light-dark()`, relative colors, `round()`, `calc-size()` and `text-box` alone. Tailwind adds a `properties` layer in front of everything for browsers without `@property`; it sits below all of Trellis and changes nothing.
- **Without it, each order breaks something.** Tailwind first: `trellis` is the last layer named, above `utilities`, and a utility on a Trellis element does nothing. Trellis first: `trellis` is below `base`, so preflight sets every heading role to body size and moves every box on the surface, and Tailwind's theme replaces five tokens Trellis also declares (`--font-sans`, `--font-serif`, `--font-mono`, `--ease-in`, `--ease-out`). `align.js` alone passes that page, since preflight moves everything consistently; only the comparison with Trellis alone sees it.
- **Four of Trellis's class names are Tailwind utilities** (`experiments/tailwind/names.js`, which asks Tailwind of every class in `core.css`): `grid`, `list-item`, `outline` and `snap-x`. Tailwind writes a utility for any of them it finds in any file it scans, and the utility, in the higher layer, beats Trellis: a `.list-item` becomes `display: list-item` (25 of 39 boxes move), an `.outline` draws a 1px outline, a `.snap-x` snap-scrolls. `grid` is harmless that way round (both say `display: grid`), but not the other: Trellis's `.grid` also styles every element an app gave Tailwind's `grid` utility.
- **Three things no layer order can fix.** An app's unlayered CSS beats every layer, so a token it declares on `:root` with a name Trellis uses is the app's everywhere: the first app's sheet declares seven, among them shadcn's `--accent`, a hover gray, where Trellis's is the accent. Tailwind's spacing scale is rem, not cells: in `grid-cols-3 gap-6 p-8`, three cards of three were off their lines. And Trellis's `.grid` gives a Tailwind `grid gap-x-4` a row gap of two cells.

## Options considered

The statement inside `core.css`. A statement only orders layers not yet named, so it must come before Tailwind's own; the app's entry has to carry it whichever file comes first. `core.css` keeps its comment saying so.

Importing `core.css` into a Tailwind layer (`@import "core.css" layer(trellis)`). Its own layers would nest inside, which is the same order with one more thing to get right, and Tailwind's `@import` with `layer()` is the app's concern, not Trellis's.

Renaming the three Trellis classes now. `.list-item`, `.outline` and `.snap-x` are public API, and one line in the app stops Tailwind making them, at the price of three utilities: the first app writes the `outline` utility in three files (`outline-1` and `outline-solid` do the same), and the others not at all. Renaming is a breaking change for every app that isn't on Tailwind. Not chosen; it stays possible.

Renaming `.grid`. The first app writes Tailwind's `grid` in 42 files, so excluding the utility is not an option, and loading `core.css` globally changes the gap and tracks of every one of those that does not set both. This is the one finding that needs a change to Trellis, and it is the owner's to choose: rename the primitive (`.grid-fit`, say), or keep it and have apps set gap and columns on every Tailwind grid. Left open.

Mapping Tailwind's `--spacing` to the cell (`@theme { --spacing: calc(var(--u) / 4) }`, so `p-4` is a cell). It would put every multiple of four on a line, but it shrinks every existing spacing utility in the app by a quarter at once, which is not one surface at a time. Not tested here.

## Decision

- **An app that loads Tailwind states the order first, before any `@import`, and tells Tailwind not to make three of Trellis's class names:**
  ```css
  @layer theme, base, trellis, components, utilities;
  @import "tailwindcss";
  @source not inline("list-item outline snap-x");
  ```
  The README's adoption notes and the skill say both lines and what breaks without them.
- **On a Trellis surface, a Tailwind length names cells** (`p-(--sp-3)`, `gap-(--sp-2)`, `md:w-(--sp-16)`), or the surface uses Trellis's own `.stack`, `.cluster`, `.cols` and `.grid`. Tailwind's rem scale is for what is not yet Trellis.
- **A token name both sides declare belongs to the app until the app renames it.** Moving a surface over starts by settling those names; the map from the first app's theme names to Trellis's tokens lives with that app.
- `tests/tailwind.js` runs in the matrix, in both engines, with `align.js` on the spike page twice. It fails if a safe order breaks, and also if a bare order stops breaking, since then the README is wrong.

## Consequences

The first app adds two lines to its entry and swaps three `outline` utilities. A surface it moves over reads Trellis's tokens, once it has settled `--accent` and the six other names its `:root` shares with Trellis.

Trellis's `.grid` still reaches an app's Tailwind grids. Until the owner decides, an app that loads `core.css` beside Tailwind checks its grids that set no gap or no columns.

`experiments/tailwind/dist/` is generated and committed, so the page and its test run anywhere without an install; `node build.js` (after `npm install` in that folder) rewrites it, and `node names.js` rewrites `dist/names.json`, the list of shared names. The bundle holds a copy of `core.css`, so a change to core makes it stale: `tests/tailwind.js` then skips the bundle and says so, the matrix runs the statement order in its place, and CI rebuilds the spike before every run, so CI always bundles today's core. When the app moves to a new Tailwind, the spike's `package.json` moves with it.

The matrix grows by four runs.
