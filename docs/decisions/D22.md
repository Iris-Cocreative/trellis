# D22. Safari settles text by a count of cells

## Context

Safari lacks `calc-size()`, so `settle.js` rounds text to whole cells there.

## Options considered

Pad a measured gap: WebKit's trimmed heights jitter by 1/64px with position, so corrections moved neighbors and never converged; at 5,000 blocks up to 87 were off and one changed row took 380ms. Hold a count of cells as the least height: chosen.

## Decision

Text in Safari takes `--settle-n`, a count of cells that core makes its least height. `--settle` remains for clusters and `.settle` blocks.

## Consequences

0 of 5,000 blocks off, and about 50ms for a changed row. The rhythm model is unchanged: this is how Safari reaches it. When Safari ships `calc-size()` the script half switches itself off.
