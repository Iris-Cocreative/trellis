# D80. Navigation on the shell

## Context

The kit had one navigation: `.shell`'s side column of `.shell-link`s, a tab bar under 48rem. A site, a knowledge base and most apps' public pages need more: a bar across the top, dropdowns, a footer, a contents outline, breadcrumbs and a skip link. Rule 16 left placing every float to the app, so a dropdown in a static site needed a script.

## Options considered

Weighed at the time, on a decision card in the plan, in five parts:

1. Top navigation: A, a shell variant, `.shell.cc-top`, its links folding behind a menu button into a left tray under 48rem; B, the same with the links becoming the bottom tab bar when narrow; C, a separate `.topbar` outside the shell.
2. Dropdowns: A, a `.float` opened by `popovertarget` and placed under its button by CSS anchor positioning where the browser has it, amending rule 16; B, a `details` disclosure positioned under its link; C, rule 16 as it stood, the app placing it.
3. Footer: A, `.shell-foot`, a shell area; B, no class, a composition.
4. Outline: A, `.outline`, nested links, the heading in view marked by the app; B, the same with `settle.js` marking the heading in view.
5. Breadcrumbs and skip link: A, `.crumbs` and `.skip-link`; B, neither yet.

## Decision

A in all five. `.shell.cc-top` puts `.shell-nav` in a bar across the top, four cells tall (`--shell-bar-h`) and sticky: `.shell-brand`, `.shell-links`, `.shell-nav-end`, and a `.shell-menu` button. The links are one element at every width, a `[popover]` shown in the bar when wide and opened by the menu button as a left tray under 48rem, so nothing is written twice. The card named a `.modal.cc-tray` for the tray; a popover gives the same tray without a second copy of the links, Escape and a click outside close it, and core locks the page while it is open. A dropdown is `.float.cc-anchor`, placed under its button by anchor positioning, flipping when it would leave the screen. `.shell-foot` is a shell area at every width. `.outline` rows are whole cells, each level a cell further in. `.crumbs` rows are whole cells and show only the parent, as a link back, in a box under 30rem. `.skip-link` is hidden until it takes focus.

## Consequences

- Additive. Rule 16 now says core places a `.cc-anchor` float where CSS can; following its anchor and closing when it scrolls away stay the app's job.
- The shell grid gains a foot row at every width; a shell with no foot is unchanged.
- A popover menu is not a modal: it does not trap focus. It opens after its button in the tab order and closes on Escape.
- `tests/layout.js` checks the bar, the menu tray, the dropdown's placement, the outline's rows and indent, the crumbs at both widths and the skip link, in both engines.
- A link styled as `.button` no longer shows a link's underline.
