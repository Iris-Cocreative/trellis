# D61. Disclosure as rows

## Context

In `.prose`, a `details` showed the browser's own triangle at the column's edge, with the answer flush under it, so question and answer shared a left edge and the open state barely showed. Core set only a pointer and the label weight on the summary. The owner found them awkward and asked for the contents inset and quieter.

## Options considered

Weighed at the time, on a decision card in the plan: A, inset and quiet: a drawn chevron in a two-cell margin, centered on the capitals and turning when open, and the contents in the same inset in `--details-ink`; B, A plus a hairline between consecutive details, drawn like list rows, and the summary as a full-row target with the shared states; C, the open contents as a sunken surface with a cell of padding that steps out, like a code block.

## Decision

B. The native marker is hidden; a chevron, two sides of a square turned, sits in a two-cell margin at half the cap height (R9) and turns down when open. The contents take the same inset in `--details-ink`, which is secondary text: a role, not opacity, so an image or code inside isn't faded. Consecutive details are rows, with a hairline in the middle of the gap between them, a plane on a line that adds no height. The summary is a full-row target with the shared hover and press (D58), its ground half a cell around it, and its focus ring the same half cell out.

## Consequences

A visual change to every `details` in prose, with no new class. Two variables, `--details-ink` and `--details-chevron`. The summary joins the shared state layer. An accordion in an app can use the same look by wrapping its content in `.prose`, until Accordion and table gives it a primitive.
