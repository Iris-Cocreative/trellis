# Figma: what it can't express

Code is the source, and the Figma file is generated from it (the Figma conventions, in [STATUS](../../STATUS.md)). This page is the list a designer needs before working in that file: what Trellis does that a Figma file cannot hold, what the file holds instead, and who keeps the two together. It is written before anyone designs in the file, so that nobody learns it from a build that doesn't match.

The variables come from `tools/figma-variables.js`, which reads `tokens.json` and each product layer through `math.js`, the same arithmetic `core.css` does; the components come from `tools/figma-components.js`, in two parts. Run both again whenever the code changes (below); never edit a variable or a component in Figma by hand.

## What carries over

- **Every token, named as in the code.** `sp-1`, `size-control-lg`, `r-1h`, `text-secondary`, each with its code syntax set to `var(--…)`, so a handoff reads in the code's words.
- **Two screens as modes.** Space and Type have a Phone mode (a 393pt screen, the cell 9.8125) and a Wide mode (1440pt, the cell 12). Color has Light and Dark.
- **Products as modes.** A Product collection has a mode for core, one for each product layer and one for each scope a layer holds: Core, Almanac and Quarry from `examples/`, and Interbeing with its three scopes from the scopes study (`experiments/scopes/interbeing.css`), the one layer that has them. It holds what a product turns: each role's size and line at both screens, every color in both themes, the families and weights, and the shape and density knobs. Type and Color alias it, and a knob aliases the variable the layer names (Quarry's `--shape-card: var(--r-q)` is `radius/r-q`, at the frame's own screen). A frame picks a product, a screen and a theme by three modes, with one set of layers. Each product's own night is in its Dark values: a night ground of another hue (`--seed-night`), a dusk (`--night-lift`), a paper that is not white (`--day-depth`), an accent and an ink of their own at night (`--seed-accent-night`, `--seed-ink-night`). So Color keeps two modes: a dusk is still dark, and it belongs to a product, not to every product at once.
- **Scopes as a Product mode on an inner frame.** A scope (D96), a product nested in a product, is a mode of its own, `Interbeing › Monastery`, worked out with what its layer's root set carried in and what nobody set following again from the scope's own seeds. Set it on an inner frame, as `data-product` sits on an inner element: Figma takes the nearest frame's mode, as CSS takes the nearest scope. A mood (`data-theme` on a scope) is the same frame in the Dark Color mode too. The Screens section has an Interbeing page with three scopes side by side, Monastery at night, and a flat thread with a composer.
- **Auto layout bound to the counts.** Gaps and padding bind to the space variables, corners to the radius variables, heights to the control sizes.
- **Type roles as text styles,** their size and line height bound to the Type variables, trimmed to the capitals and the baseline (Figma's vertical trim: cap height to baseline). Trimmed, a descender hangs below its box, as it does in the code: a frame that holds text must not clip its content, or the last line loses its tails.
- **Products and themes as modes on a frame.** A screen is built once; setting a frame's Product to Quarry, its Space and Type to Phone and its Color to Dark shows Quarry on a phone in the dark theme, with no second set of layers. The file's Screens section shows one settings card in each product, wide and light, phone and dark.
- **Components named by their class chains:** `button icon-button` with kind=cc-ghost and size=cc-sm is `class="button icon-button cc-ghost cc-sm"`: a component set per primitive, its variant properties the modifiers, so the name a designer picks is the class a builder writes. Each component's description gives its markup. Built: button (kind, size, state), button icon-button, tag (kind with the seven stages, emphasis, size), avatar (kind with cc-space, ring with cc-plain, size), badge, dot (kind with cc-accent and the stages, fill with cc-ring), switch, range, input (state, size), field, tab, tabs, tabs cc-seg, options-card-item, options-card, tooltip, list-item (mark, unread, state), composer (state), chat-item cc-flat (run, state), card (level), modal. Built from them, in a Templates section: chat-item (from with cc-own × run, the bubble), chat-reaction (mine), list cc-group (mark), member-tile (layout with cc-row), skeleton (kind with cc-block), shell (top with cc-top × width, wide and narrow), crumbs (width), outline, skip-link. A button's label takes the product's button family and weight (`--font-button`, `--fw-button`).
- **Measures core works out, worked out.** A button's padding is half its height in half cells, a tag's padding its corner, a nested card's corner its parent's less the gap: a frame can't compute, so each is a number per product and screen, read through Space as `derived/…` (`derived/control-pad`, `derived/tag-pad`, `derived/card-nest-r`, `derived/option-r`, `derived/seg-pad`, `derived/composer-btn-r`). A ring's line, a quarter of the dot between one and two lines, is `derived/dot-ring`, per screen. A hairline, one device pixel, is `space/hair` (a third of a point on the phone, half on the wide screen); the shell's columns and a bubble's measure, which core sets in cells, are `size/shell-nav-w`, `size/shell-aside-w` and `size/chat-measure`.
- **A product's color knobs as colors.** The bubble's knobs (`--chat-own-bg`, `--chat-own-ink`, `--chat-bubble-edge`, D99) are Color variables, each an alias of the role the product's layer names, in each theme. A knob a layer sets to a mix (`color-mix()`) can't be carried, and `tests/contract.js` says so.

## What it can't, and what stands in

| Trellis does | Figma can't, because | In the file |
|---|---|---|
| **Type follows its space.** A role's size is a straight line between its narrow and wide ends, read from its container's width. | A variable is one number per mode, with no arithmetic, and a frame does not know its width. | Two samples, Phone and Wide. A card's type in a narrow column is the screen's, not the column's: mark it, and the code will be smaller there. |
| **The cell follows the screen** and the reader's text size, up to a cap, and the fit makes whole cells span a fitted screen. | No variable follows a width, and no text-size setting exists. | The cell at two screens. A Large text mode (the 312% case) can be added; until then, nobody checks it in Figma. |
| **Everything rounds to whole cells.** A block's height rounds up so what follows starts on a line; a control is never shorter than its own type; a wrapped label hangs. | Auto layout hugs its contents to any height. | The designer snaps by hand: a fixed height in cells where a box must keep the rhythm, and a layout grid of the cell to check against. The code will correct a box that hugs to 61pt; the file won't show it. |
| **Headlines stand on a line.** H1 to H3 have whole-cell line heights and the last baseline on a cell line. | Expressible as a number, not as the rule. | The generated line height already stands; a designer who changes a size must regenerate, not type a new one. |
| **Color is derived.** Nine seeds follow from the accent; the dark theme lifts each; ink on a fill is chosen by contrast. | Variables alias, but don't compute: there is no relative color, no `color-mix()`, no `light-dark()`. | Every role resolved, in both themes and every product, and ink on each solid hue as its own role (`color/on-kind-person`). Changing the accent in Figma changes only the accent: change it in the product layer or the token file and regenerate. |
| **One state layer.** Hover, press and selected mix a control's own ink into its fill by a share; a tag's ground and edge are its hue at a share. | No mix, and a paint's own opacity is dropped on an instance: a 6% hover comes out solid. | Each share is a color with its alpha in it, `color/tint/<role>/<percent>` (`color/tint/text/6`), its code syntax the `color-mix()` it stands for; a component variant per state. Never set a paint's opacity in this file. Hover is prototype-only. |
| **Depth is read from nesting.** A card in a card is the next ground and its corner is concentric. | A component doesn't know what it is inside. | A `level` property (1, 2, 3) on surfaces; the designer sets it. Corners per level are precomputed. |
| **Context changes variables.** `.cc-dense`, a container that turns a column into a tab bar. | No inheritance of variables through a subtree, no container queries. | Variants for each context that changes a measure (dense, a segmented control's tabs) and for the shell at each width. A product's own density knobs are its mode. |
| **A product sets case and tracking.** Quarry's tags and labels are uppercase and tracked; a heading tracks tighter; a button may have a case and spacing of its own (`--button-case`, `--button-tracking`, D100), and an eyebrow may differ from the label (`--eyebrow-case`, `--eyebrow-tracking`, D102). | Case belongs to a text style, not a variable, so a mode can't change it; tracking binds only in pixels. | Not carried: the file's tags, labels, eyebrows and buttons are in sentence case and untracked in every product (a button's family and weight are carried). Set them by hand on a mockup, and know the code does it for you. |
| **A scope carries what its product chose.** A scope rule applies inside any product that holds it, and takes that product's choices. | A mode holds values, not the rule that made them. | Each scope is worked out once, with its own layer's root, and named for it (`Interbeing › Chapel`). Inside another product's frame it still shows Interbeing's choices. |
| **A row's mark sits on its first line's capitals** (`.list-mark`, a box `1cap` tall, D104), however many lines the row runs to. | No length is a capital's height. | The mark is centered on a one-line title's trimmed box, which is the capitals. A title that wraps carries its mark to the middle of the block; the code doesn't. `--list-align: center` is not a variant. |
| **A list draws its hairlines** between rows, inset to the text's edges, as a plane that adds no height. | A rule is a stroke on a box, and the box is the row. | A plain list-item has no rule. `list cc-group` draws one between its rows: a box with no height between them, its hairline hanging out of it from the text's start to the surface's edge. |
| **A clamp keeps its descenders** (`.u-clamp`, D105): a clip from the top, and `settle.js` trims the box where Safari doesn't. | Not expressible. | Figma's own truncation (Truncate text, max lines) stands in; whether it keeps the tails is Figma's. |
| **A ring's line follows the dot's size**, a quarter of it between one and two lines (D103). | A stroke weight is a number per mode. | `derived/dot-ring` at the half-cell dot, per screen. A larger ring dot in a mockup draws the half-cell line. |
| **The conversation pieces** (D99): bubbles, quotes, files, links, reactions, dividers, typing. | Expressible; not all built yet. | The composer, the flat row, the bubble (with its knobs) and a reaction are components; quotes, files, links, dividers and typing are the code's for now. |
| **A skeleton shimmers**, a gradient of the ink at 8% and 16% moving across it. | A gradient's stops don't bind to variables, and nothing moves. | The 8% ground, still. |
| **The shell answers to its own width** (a container query): three columns, the aside under main below 72rem, a tab bar or a folded top bar below 48rem. | A frame doesn't know its width. | A `width` property, wide (1200) and narrow (a 393pt phone). The middle step, the aside under main, is not drawn; nor is the open menu tray. |
| **An edge is a plane.** A card's edge is drawn on its grid line's pixels, one line wide, stepping out a cell. | A stroke is inside, outside or centered on a box, at any position. | Strokes inside, on boxes placed on the grid. A nested card's step out (`derived/card-nest-out`) is drawn by making the box that much wider. Pixel precision is the code's. |
| **An avatar's ring follows its size.** A gap and a ring as spread shadows, a quarter cell from 4u up. | An effect's spread is a number. | Numbers at the wide screen; on a phone the ring is a hair too thick. |
| **Floats** sit in the top layer, are placed by their anchor, flip at the screen's edge and close when it scrolls away. | Overlays exist only in prototypes, placed by hand. | A float is drawn beside its anchor where it would open, and the flip is not shown. |
| **A role's size is a class.** `.t-h1` sets a size and a line; there is no `--h1-size` to name. | Code syntax names a variable. | A role's two variables give `.t-h1` as their code syntax. |
| **Touch targets.** On touch every control's hit area is 44pt, whatever it draws. | Not drawn. | Annotated once, in the file's cover notes; nobody needs to draw it per control. |
| **Motion.** Durations and easings are tokens; the fade, the press, the trays. | Variables hold no durations; prototype transitions are set per connection. | The durations are listed as notes; a prototype sets them by hand, and is not the spec. |
| **System fonts.** Core's default is the platform's sans; the example layers name system fonts. | A file needs a family Figma has. | A family Figma has stands in, chosen in `tools/figma-variables.js` (`STAND_IN`): Inter for the system sans, Gelasio (drawn to Georgia's measures) for Georgia, Hanken Grotesk for Helvetica, Lato for Gill Sans, Source Serif 4 for Iowan and Palatino; Interbeing's web fonts (Geist, Halant, Cormorant Garamond, Alegreya Sans) as themselves. A family that lacks a weight another product sets (Alegreya Sans has no 600) is loaded in the weights it has; only a text style's own font must exist. A product with its own web fonts names them in its layer, and its mode carries them. |
| **Forced colors and reduced motion.** | Not expressible. | The code's alone. |

## Regenerating the file

Three plugin scripts write the file, in this order. All work by name, so they can run on it again and again:

1. `node tools/figma-variables.js --plugin` prints a script that writes the four collections, their modes and every variable, and the thirteen text styles bound to them. A variable that exists is updated in place and keeps every binding to it; one the generator no longer writes is removed.
2. `node tools/figma-components.js --plugin primitives` prints a script that builds every primitive from those variables, in the section Components (`tools/figma-primitives.js`).
3. `node tools/figma-components.js --plugin templates` prints a script that builds what is made of the primitives, in the section Templates, and the Screens (`tools/figma-templates.js`).

The components travel in two parts because a script can't be longer than 50,000 characters: each part is the shared kit (`tools/figma-kit.js`: the variables by name, the fonts, the helpers) and its own body, as the variables script is a template (`tools/figma-plugin.js`) and the data `figma-variables.js` puts in it. The parts own three sections on the first page, Components, Templates and Screens: the first removes all three, the second builds two of them again; anything else on the page is left alone. A run that fails takes back what it made. `node tools/figma-components.js` prints each part's length.

Run them as a development plugin, or through an agent's Figma tool, which takes a script of up to 50,000 characters and can't fetch, so the data travels inside the script. To fit, a product's tint (`light/tint/<role>/<pct>`) travels as 0 and the plugin works it out from its role's hex and the share in its name. A call that throws is taken back whole: if the variables script fails at its text styles, the variables were not written either. `tests/contract.js` checks that each script parses, that each fits, that every variable the components bind and every role they paint is generated, that every scope of every layer the generator reads is a Product mode, and that each Product mode's colors are the ones the contract itself composes and checks for that layer or scope.

## Who keeps them together

The file follows the code, one way. A change a designer makes in Figma is a proposal: it reaches the code as a change to a token, a knob or a primitive, through the same review as any other, and then the file is generated again. Where the two disagree, the code is right and the file is stale.
