# Figma: what it can't express

Code is the source, and the Figma file is generated from it (the Figma conventions, in [STATUS](../../STATUS.md)). This page is the list a designer needs before working in that file: what Trellis does that a Figma file cannot hold, what the file holds instead, and who keeps the two together. It is written before anyone designs in the file, so that nobody learns it from a build that doesn't match.

The variables come from `tools/figma-variables.js`, which reads `tokens.json` and each product layer through `math.js`, the same arithmetic `core.css` does; the components come from `tools/figma-components.js`. Each travels in parts. Run them all again whenever the code changes (below); never edit a variable or a component in Figma by hand.

## What carries over

- **Every token, named as in the code.** `sp-1`, `size-control-lg`, `r-1h`, `text-secondary`, each with its code syntax set to `var(--…)`, so a handoff reads in the code's words.
- **Two screens as modes.** Space and Type have a Phone mode (a 393pt screen, the cell 9.8125) and a Wide mode (1440pt, the cell 12). Color has Light and Dark.
- **Products as modes.** A Product collection has a mode for core, one for each product layer and one for each scope a layer holds: Core, Almanac and Quarry from `examples/`, and Grove, the community app as the scopes study draws it, with its three scopes (`experiments/scopes/grove.css`), the one layer that has them. It holds what a product turns: each role's size and line at both screens, every color in both themes, the families and weights, and the shape and density knobs. Type and Color alias it, and a knob aliases the variable the layer names (Quarry's `--shape-card: var(--r-q)` is `radius/r-q`, at the frame's own screen). A frame picks a product, a screen and a theme by three modes, with one set of layers. Each product's own night is in its Dark values: a night ground of another hue (`--seed-night`), a dusk (`--night-lift`), a paper that is not white (`--day-depth`), an accent and an ink of their own at night (`--seed-accent-night`, `--seed-ink-night`). So Color keeps two modes: a dusk is still dark, and it belongs to a product, not to every product at once.
- **Scopes as a Product mode on an inner frame.** A scope (D96), a product nested in a product, is a mode of its own, `Grove › Lodge`, worked out with what its layer's root set carried in and what nobody set following again from the scope's own seeds. Set it on an inner frame, as `data-product` sits on an inner element: Figma takes the nearest frame's mode, as CSS takes the nearest scope. A mood (`data-theme` on a scope) is the same frame in the Dark Color mode too. The Screens section has a Grove page with three scopes side by side, the lodge at night, and a flat thread with a composer.
- **Auto layout bound to the counts.** Gaps and padding bind to the space variables, corners to the radius variables, heights to the control sizes.
- **Type roles as text styles,** their size and line height bound to the Type variables, trimmed to the capitals and the baseline (Figma's vertical trim: cap height to baseline). Trimmed, a descender hangs below its box, as it does in the code: a frame that holds text must not clip its content, or the last line loses its tails.
- **Products and themes as modes on a frame.** A screen is built once; setting a frame's Product to Quarry, its Space and Type to Phone and its Color to Dark shows Quarry on a phone in the dark theme, with no second set of layers. The file's Screens section shows one settings card in each product, wide and light, phone and dark.
- **Components named by their class chains:** `button icon-button` with kind=cc-ghost and size=cc-sm is `class="button icon-button cc-ghost cc-sm"`: a component set per primitive, its variant properties the modifiers, so the name a designer picks is the class a builder writes. Each component's description gives its markup. Built: button (kind, size, state), button icon-button, tag (kind with the seven stages, emphasis, size), avatar (kind with cc-space, ring with cc-plain, size), badge, dot (kind with cc-accent and the stages, fill with cc-ring), switch (checked with mixed, state), choice (kind checkbox or radio × checked with mixed × state with invalid and disabled × size, D109), range, input (element: input, select or textarea, × state × size), field, tab, tabs, tabs cc-seg, options-card-item, options-card (a heading, a rule), tooltip, list-item (mark, unread, state), composer (state), card (level), modal, modal cc-tray (side). The conversation (D99), in a Thread section: chat-quote (state), chat-file (tint), chat-link (media), chat-reaction (mine), chat-divider (kind with cc-new), chat-typing (thread with cc-flat), chat-item (from with cc-own × run × state with cc-removed, the bubble), chat-item cc-flat (run × state with its actions on hover), chat-item cc-wall, chat-item cc-system. A message's properties show what it carries: a quote, a file, a link, reactions, "(edited)", or no words at all. Built from the primitives, in a Templates section: list cc-group (mark), `list-item[data-trellis-swipe]` (its list-actions, drawn open), avatar-stack (with avatar-more), an avatar with its avatar-dot, prose, member-tile (layout with cc-row), skeleton (kind with cc-block), media (kind with cc-round × focus × fill, D108), `card:has(.card-link)` (media: inside, cc-bleed, cc-bleed-start, cc-fill × state, D108), `list-item:has(.list-link)` (state), shell (top with cc-top × width, wide and narrow), crumbs (width), outline, skip-link. A tag's properties show its tag-dot and its tag-remove. A button's label takes the product's button family and weight (`--font-button`, `--fw-button`). A component named by a selector, `card:has(.card-link)`, is a part with a class inside it: the class goes on the title, not the card. Two modifiers are instance settings, not variants: `.button.cc-block` is an instance whose width is set to Fill, and a tag for what isn't here yet (`--tag-edge-style: dashed`) is an instance whose stroke is dashed (4, 2); the events screen shows both.
- **Measures core works out, worked out.** A button's padding is half its height in half cells, a tag's padding its corner, a nested card's corner its parent's less the gap: a frame can't compute, so each is a number per product and screen, read through Space as `derived/…` (`derived/control-pad`, `derived/tag-pad`, `derived/card-nest-r`, `derived/option-r`, `derived/seg-pad`, `derived/composer-btn-r`). A ring's line, a quarter of the dot between one and two lines, is `derived/dot-ring`, per screen. A media frame's corner in a card, concentric with the card's, is `derived/media-r` (D108); its height, twelve cells, is `size/media-h`, and a full bleed's eighteen `size/media-h-fill`. A hairline, one device pixel, is `space/hair` (a third of a point on the phone, half on the wide screen); the shell's columns a tray's width, and the measures of a bubble, a file and a link, which core sets in cells, are `size/shell-nav-w`, `size/shell-aside-w`, `size/tray-w`, `size/chat-measure`, `size/chat-file-measure` and `size/chat-link-measure`; a textarea's three lines, `size/textarea-h`.
- **A product's color knobs as colors.** The bubble's knobs (`--chat-own-bg`, `--chat-own-ink`, `--chat-bubble-edge`, D99) are Color variables, each an alias of the role the product's layer names, in each theme. A knob a layer sets to a mix (`color-mix()`) can't be carried, and `tests/contract.js` says so.

## What it can't, and what stands in

| Trellis does | Figma can't, because | In the file |
|---|---|---|
| **A product's own colors** (`--seed-own-gold`, `.u-seed`, `.cc-seed`, D117) are worked out on the element that takes one, from whatever name a layer gave. | A variable is made by name, and a mode can't hold a color the other modes have not. | Not in the file: no layer in the repository names one. A layer that does needs, for each name, its fill, ink, solid and solid ink in both themes in Product, the same four in Color, the tints and the tag's and dot's `cc-seed` variants; until then use its hex, and mark it. |
| **Type follows its space.** A role's size is a straight line between its narrow and wide ends, read from its container's width. | A variable is one number per mode, with no arithmetic, and a frame does not know its width. | Two samples, Phone and Wide. A card's type in a narrow column is the screen's, not the column's: mark it, and the code will be smaller there. |
| **The cell follows the screen** and the reader's text size, up to a cap, and the fit makes whole cells span a fitted screen. | No variable follows a width, and no text-size setting exists. | The cell at two screens. A Large text mode (the 312% case) can be added; until then, nobody checks it in Figma. |
| **Everything rounds to whole cells.** A block's height rounds up so what follows starts on a line; a control is never shorter than its own type; a wrapped label hangs. | Auto layout hugs its contents to any height. | The designer snaps by hand: a fixed height in cells where a box must keep the rhythm, and a layout grid of the cell to check against. The code will correct a box that hugs to 61pt; the file won't show it. |
| **Headlines stand on a line.** H1 to H3 have whole-cell line heights and the last baseline on a cell line. | Expressible as a number, not as the rule. | The generated line height already stands; a designer who changes a size must regenerate, not type a new one. |
| **Color is derived.** Nine seeds follow from the accent; the dark theme lifts each; ink on a fill is chosen by contrast. | Variables alias, but don't compute: there is no relative color, no `color-mix()`, no `light-dark()`. | Every role resolved, in both themes and every product, and ink on each solid hue as its own role (`color/on-kind-person`). Changing the accent in Figma changes only the accent: change it in the product layer or the token file and regenerate. |
| **One state layer.** Hover, press and selected mix a control's own ink into its fill by a share; a tag's ground and edge are its hue at a share. | No mix, and a paint's own opacity is dropped on an instance: a 6% hover comes out solid. | Each share is a color with its alpha in it, `color/tint/<role>/<percent>` (`color/tint/text/6`), its code syntax the `color-mix()` it stands for; a component variant per state. Never set a paint's opacity in this file. Hover is prototype-only. |
| **Depth is read from nesting.** A card in a card is the next ground and its corner is concentric. | A component doesn't know what it is inside. | A `level` property (1, 2, 3) on surfaces; the designer sets it. Corners per level are precomputed. |
| **Context changes variables.** `.cc-dense`, a container that turns a column into a tab bar. | No inheritance of variables through a subtree, no container queries. | Variants for each context that changes a measure (dense, a segmented control's tabs) and for the shell at each width. A product's own density knobs are its mode. |
| **A product sets case and tracking.** Quarry's tags and labels are uppercase and tracked; a heading tracks tighter; a button may have a case and spacing of its own (`--button-case`, `--button-tracking`, D100), and an eyebrow may differ from the label (`--eyebrow-case`, `--eyebrow-tracking`, D102). | Case belongs to a text style, not a variable, so a mode can't change it; tracking binds only in pixels. | The text styles carry core's: the label and the eyebrow uppercase and tracked, headings tracked in. No product's own: every product's labels are uppercase here, and its tags and buttons in sentence case, untracked (a button's family and weight are carried). Set them by hand on a mockup, and know the code does it for you. |
| **A scope carries what its product chose.** A scope rule applies inside any product that holds it, and takes that product's choices. | A mode holds values, not the rule that made them. | Each scope is worked out once, with its own layer's root, and named for it (`Grove › Lantern`). Inside another product's frame it still shows Grove's choices. |
| **A row's mark sits on its first line's capitals** (`.list-mark`, a box `1cap` tall, D104), however many lines the row runs to. | No length is a capital's height. | The mark is centered on a one-line title's trimmed box, which is the capitals. A title that wraps carries its mark to the middle of the block; the code doesn't. `--list-align: center` is not a variant. |
| **A list draws its hairlines** between rows, inset to the text's edges, as a plane that adds no height. | A rule is a stroke on a box, and the box is the row. | A plain list-item has no rule. `list cc-group` draws one between its rows: a box with no height between them, its hairline hanging out of it from the text's start to the surface's edge. |
| **A clamp keeps its descenders** (`.u-clamp`, D105): a clip from the top, and `settle.js` trims the box where Safari doesn't. | Not expressible. | Figma's own truncation (Truncate text, max lines) stands in; whether it keeps the tails is Figma's. |
| **A ring's line follows the dot's size**, a quarter of it between one and two lines (D103). | A stroke weight is a number per mode. | `derived/dot-ring` at the half-cell dot, per screen. A larger ring dot in a mockup draws the half-cell line. |
| **A card is one link** (D108): the title's `::before` covers the card, the card's own controls are raised above it, and hover, press, selected and the focus ring are drawn on the cover. | No layer can be a link's hit area, nothing in a component stacks above its own top layer, and hover is a prototype state. | A `card-link::before` layer over the card, a variant per state (6%, 12%, 10% with the accent mark). It is drawn over everything, the tag and the button too; in the code those sit above it and keep their own clicks. The focus ring is the code's. A covered row (`list-item:has(.list-link)`) is the same, on the row. |
| **An image fills its frame by cover at a focal point** (`.media`, `object-fit: cover`, `--media-focus`, D108). | An image fill covers a frame only from its middle (Fill); any other focus is a crop (Crop), worked out for one size, which stretches when the frame is resized. A gradient's stops don't bind, and the file can't fetch an image. | The middle is Figma's Fill. Off the middle (50% 25%) the file draws a crop made at the frame's size at the wide screen: resize the frame and crop again. Every frame holds a stand-in picture the script draws; replace the fill with the real image. A full bleed's scrim is a plain gradient to 80% black. On it the code draws a control with no fill of its own (a plain or ghost button, a tinted tag, a choice, a switch, a tab) in white, its edge a share of white, and its focus ring white, in both themes; the file's full bleed has white words and a solid tag, and its ghost icon button is still in the text's ink. Until the file is regenerated, override the ink by hand there, or use a solid tag and a primary button, which keep their own fill. A frame whose width fills its column is a fixed width in a component. |
| **A choice's box is the native input** (D109): the browser draws checked, mixed (set from script), invalid once touched and disabled; hover and press are the state layer on the box; on touch the row grows to 44pt; a wrapped label (`.cap-center`) keeps its box on the first line. | States are variants: nothing is a script's property, nothing grows on touch, and a label in an instance doesn't carry the box with it when it wraps. | A `choice` set with every state and size, and the switch's mixed state. Hover and press, the touch area and a wrapped label are the code's. Mixed is a variant; the code needs a line of script (`indeterminate`). |
| **The conversation pieces** (D99). A quote, a link and a row of reactions round up to whole cells; a file's name is cut with an ellipsis at 26 cells; "(edited)" runs on in the words; a removed message is italic; the typing dots pulse; a thread is a stack whose runs are a cell apart; a row's actions and a quote's and a link's hover are states. | Nothing rounds a hugged box; a hugged line doesn't truncate; a property shows or hides a whole layer, not part of a text; a style's italic would lose its family in another product; nothing moves. | Every piece is a component. The quote truncates at two lines; a file's name truncates when an instance sets it. "(edited)" stands at the end of the words' box, removed words are upright, and the dots are still, at the 60% the code draws under reduced motion. A run is a frame with a cell between its messages, or none between flat rows, which pad half of it each. On a phone a bubble's words wrap at the wide measure: set the text's width. |
| **A card's padding clears its corner** (D113): it grows by whole cells where a product's padding falls inside the corner's curve. | A mode holds the knob, not the rule. | The knob's padding. No layer the file holds falls short; a rounder one must be checked. |
| **A shell keeps no column for an aside it doesn't have**, and a side column's brand is not in the tab bar. | A variant is drawn, not worked out. | Every shell is drawn with its aside: delete it from a detached copy and let main fill. |
| **A context tightens what is in it** (`.cc-dense`: a card, a list, a field, a tag, a button, a bubble, tabs). | A mode is a product's, a screen's or a theme's, and no variable follows a subtree. | Not drawn as variants, but where the context's measure is a size that exists: use a small tag, button or input in a dense box, and pad a dense card or a dense row a cell or a half by hand. |
| **The mono family** (`.t-mono`, `--font-mono`, code in prose). | Expressible; not built. | No mono text style or variable: set a mono face by hand on a mockup. |
| **A tag's remove button** pulls its box into the tag's padding. | Auto layout has no negative margin. | The mark alone, after the words, at the tag's own padding. |
| **An avatar stack** overlaps by half a cell, each face parted from the one under it by two lines of the surface. | A negative gap doesn't bind, and a stroke's role is one color. | The overlap is a number at the wide screen and the knock is the page's ground: on a card, set it to the card's. |
| **A swipe** slides a row to its actions (`presets.js`), and a tray slides in from its side. | Prototype motion, per connection. | A row drawn open; a tray drawn open, on its own. |
| **An icon is the stroke's own drawing,** any size, in the text's ink. | An instance can't hold another drawing without a swap of components, and the file has no icon set. | A plus stands for any icon. Replace the vector in an instance's detached copy, or draw over it. |
| **A skeleton shimmers**, a gradient of the ink at 8% and 16% moving across it. | A gradient's stops don't bind to variables, and nothing moves. | The 8% ground, still. |
| **The shell answers to its own width** (a container query): three columns, the aside under main below 72rem, a tab bar or a folded top bar below 48rem. | A frame doesn't know its width. | A `width` property, wide (1200) and narrow (a 393pt phone). The middle step, the aside under main, is not drawn; nor is the open menu tray. The tab bar's current link carries its mark on its top edge, as the code draws it. |
| **An edge is a plane.** A card's edge is drawn on its grid line's pixels, one line wide, stepping out a cell. | A stroke is inside, outside or centered on a box, at any position. | Strokes inside, on boxes placed on the grid. A nested card's step out (`derived/card-nest-out`) is drawn by making the box that much wider. Pixel precision is the code's. |
| **An avatar's ring follows its size.** A gap and a ring as spread shadows, a quarter cell from 4u up. | An effect's spread is a number. | Numbers at the wide screen; on a phone the ring is a hair too thick. |
| **Floats** sit in the top layer, are placed by their anchor, flip at the screen's edge and close when it scrolls away. | Overlays exist only in prototypes, placed by hand. | A float is drawn beside its anchor where it would open, and the flip is not shown. |
| **A role's size is a class.** `.t-h1` sets a size and a line; there is no `--h1-size` to name. | Code syntax names a variable. | A role's two variables give `.t-h1` as their code syntax. |
| **Touch targets.** On touch every control's hit area is 44pt, whatever it draws. | Not drawn. | Annotated once, in the file's cover notes; nobody needs to draw it per control. |
| **Motion.** Durations and easings are tokens; the fade, the press, the trays. | Variables hold no durations; prototype transitions are set per connection. | The durations are listed as notes; a prototype sets them by hand, and is not the spec. |
| **System fonts.** Core's default is the platform's sans; the example layers name system fonts. | A file needs a family Figma has. | A family Figma has stands in, chosen in `tools/figma-variables.js` (`STAND_IN`): Inter for the system sans, Gelasio (drawn to Georgia's measures) for Georgia, Hanken Grotesk for Helvetica, Lato for Gill Sans, Source Serif 4 for Iowan and Palatino; the community app's web fonts (Geist, Halant, Cormorant Garamond, Alegreya Sans) as themselves. A family that lacks a weight another product sets (Alegreya Sans has no 600) is loaded in the weights it has; only a text style's own font must exist. A product with its own web fonts names them in its layer, and its mode carries them. |
| **Forced colors and reduced motion.** | Not expressible. | The code's alone. |

## Regenerating the file

Four plugin scripts write the file, in this order. All work by name, so they can run on it again and again:

1. `node tools/figma-variables.js --plugin product` prints a script that writes the Product collection, and `--plugin space-type-color` one that writes Space, Type and Color and the thirteen text styles bound to them. Each makes all four collections and their modes; a variable that exists is updated in place and keeps every binding to it; one the generator no longer writes is removed from that part's collections. A variable one part aliases and the other writes is made empty, for the other part to fill, so either can run first.
2. `node tools/figma-components.js --plugin primitives` prints a script that builds every primitive from those variables, in the section Components (`tools/figma-primitives.js`).
3. `--plugin thread` builds the conversation, in the section Thread (`tools/figma-thread.js`).
4. `--plugin templates` builds what else is made of the primitives, in the section Templates (`tools/figma-templates.js`).
5. `--plugin screens` builds the section Screens, of all three (`tools/figma-screens.js`).

Each comes in parts because a script can't be longer than 50,000 characters. The variables script is a template (`tools/figma-plugin.js`) and the data `figma-variables.js` puts in it; each components part is the shared kit (`tools/figma-kit.js`: the variables by name, the fonts, the sections, the helpers), what it shares with others (`tools/figma-built.js`: the components built so far; `tools/figma-photo.js`: the stand-in picture) and its own body, with the files' headers and the comments on lines of their own left out. The component parts own four sections on the first page, Components, Thread, Templates and Screens. A part removes and builds its own; primitives removes all four, and thread and templates remove the Screens, which are made of them, so after any part run the ones below it. Anything that isn't one of those sections is left alone. A run that fails takes back what it made.

Before a part removes a section, look at what is in it: `node tools/figma-inventory.js --plugin` prints a script that reads the file's sections, layer by layer, and `node tools/figma-inventory.js` the same from the scripts, run against a stand-in for Figma's API. When the two agree, a section holds what the scripts drew and nothing else; when they don't, look for what was made by hand before it is lost. After the run they must agree again. They compare names, types, texts, descriptions and properties, not sizes or colors: for those, take screenshots. `node tools/figma-variables.js --lengths` and `node tools/figma-components.js` print each part's length.

When only a few variables are new, a delta is cheaper than a whole part: `--plugin <part> --only <regex>` writes just the variables whose names match and removes nothing. To check the file against the generator afterwards, `node tools/figma-variables.js --checksum` prints the number of values and a checksum of them all (every variable in every mode), and `--plugin checksum` prints a script that works out the same in the open file. They match when the file holds what the code says.

Run them as a development plugin, or through an agent's Figma tool, which takes a script of up to 50,000 characters and can't fetch, so the data travels inside the script. To fit, a product's tint (`light/tint/<role>/<pct>`) travels as 0 and the plugin works it out from its role's hex and the share in its name. A call that throws is taken back whole: if the variables script fails at its text styles, the variables were not written either. A mode is matched by name, so when a product is renamed (a layer's `data-product`), rename its mode in the file first, in place; a run would otherwise remove the old mode and add a new one, and every frame set to it would lose its mode. `tests/contract.js` checks that each script parses, that each fits, that the variables parts between them write every collection once, that the component parts run in order against the stand-in, that every variable the components bind and every role they paint is generated, that every scope of every layer the generator reads is a Product mode, and that each Product mode's colors are the ones the contract itself composes and checks for that layer or scope.

## Who keeps them together

The file follows the code, one way. A change a designer makes in Figma is a proposal: it reaches the code as a change to a token, a knob or a primitive, through the same review as any other, and then the file is generated again. Where the two disagree, the code is right and the file is stale.
