# R16 · Floating surfaces align to their anchor

## Statement

Floating surfaces align to their anchor, not the page grid. One `.float` for every popover, options card and tooltip. Core puts it in the top layer at a fixed position and defines its motion once. A float marked `.cc-anchor` is placed by its anchor where the browser has CSS anchor positioning: under the button that opened it (the button that opens a popover is its anchor, so no names are needed), flipping when it would leave the screen. Elsewhere, and for following the anchor and closing when it scrolls away, the app does it.

## Why

A float belongs to what opened it. On the grid it would drift from its anchor whenever the anchor isn't on a cell boundary, which inside a scroller is most of the time.

## The failure it prevents

A menu that stays put while the list it came from scrolls away beneath it.

## How it is checked

In `core.css`, `.float[popover]` is fixed, in the top layer (`--z-float`), with one enter and exit transition. `tests/layout.js` opens the specimen's navigation dropdown, a `.float.cc-anchor`, and fails it unless it lands under its button, in both engines.

## Example

The specimen's roles menu opens under its button and closes when the scroller carries the button out of view: the specimen's own script places it and closes it, as an app would.

## Exceptions

None.

## History

Until D69 the rule promised following and closing as well, and was questioned: the code kept half of it. `core.css` puts `.float[popover]` in the top layer at a fixed position and defines its motion once. Following the anchor and closing when it scrolls away are done by the specimen's own script, not by Trellis, so a consumer gets neither for free. Open as "Floats that follow and close".

D80 added `.cc-anchor`: where the browser has anchor positioning, core now places a float under the button that opened it.
