# R20 · Every sideways scroller can be reached by keyboard

## Statement

A region that scrolls sideways can take focus, or holds something that can. A `.rail` and a `.board` carry their tab stop in the markup: `tabindex="0"`, `role="group"` and an `aria-label`. A `pre` or a `table` in `.prose` gets one from `settle.js` when it overflows with nothing focusable inside, and gives it back when it no longer overflows.

## Why

A keyboard scrolls only what it can focus. Chrome and Firefox make a scroller with nothing focusable inside focusable on their own; Safari does not, and every iPhone web view is Safari's engine. Rails and boards carry their stop in the markup because only the author has the words for their label. Prose comes from an editor and cannot carry one, so the runtime adds it.

## The failure it prevents

A code sample, a wide table or a rail of cards whose right-hand part a keyboard user can never see.

## How it is checked

`tests/align.js` finds every element whose computed `overflow-x` is `auto` or `scroll` and whose content is wider than its box, and fails any that has no explicit tab stop and nothing focusable inside. It runs in all 21 matrix runs, in Chromium and WebKit. The React contract's review checklist asks the same of rails and boards.

## Example

The code sample in the specimen's prose post overflows on a 393 phone: `settle.js` gives it `tabindex="0"` and `data-trellis-reach`. On a 1440 screen it fits, and both are taken back.

## Exceptions

An element with a `tabindex` of its author's own is never touched. A closed `details`, a closed popover or dialog, or a hidden element is not checked, since nothing in it can be seen.
