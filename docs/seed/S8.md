# S8 Why relationships replace values

## What it is

The premise of Trellis. Interfaces drift. Trellis replaces values with relationships, and relationships with checked rules.

## Why

An audit of two working apps, made before Trellis existed, found dozens of font sizes, scores of spacing values and radii, thousands of one-off utility values, and many separate builds of the same avatar, modal and pill. Nothing stopped the drift, so it drifted.

A value can always be nudged by one pixel for one screen, and each nudge looks harmless. A relationship can't be nudged without changing everything that shares it, so the nudge either becomes a deliberate change or doesn't happen. A rule that is checked can't be broken quietly at all.

## How it is computed, in plain words

Three steps.

1. **Values become relationships.** Every space is a number of cells ([S1](S1.md)). Every type size is a step on a ratio between two anchors ([S2](S2.md)). Every color is a semantic role, a light and dark pair. A product reshapes all of it by turning knobs on `:root`, never by redrawing a primitive (R14).
2. **Relationships become rules.** Edges land on lines, space between blocks is whole cells, one concept has one primitive, context changes variables: rules R1 to R19 and F1 to F6.
3. **Rules become checks.** Tests fail when a rule breaks: `tests/align.js` puts every edge and every block of text on a cell line, `tests/pixel.js` checks card edges at the device pixel, `tests/contract.js` holds products to knobs and the Public API to the code.

Not yet checked: no raw values outside the token layer, every class registered in the consuming app, and inline styles setting variables only. Until those lints exist, they are the pull request checklist in `REACT.md`.

## Where it lives in the code

- `README.md`: Why, and Enforcement.
- `tokens.json`: the values every platform shares, in cells and points.
- `product.template.css`: every knob a product may turn.
- `tests/`: the checks, run in CI on every push and pull request.
