# S4 Context

## What it is

Both measures answer to the box they are in. Type sizes come from the container, not the window. Layout parts respond to their container, not the screen. And a context changes variables, never markup.

## Why

A component should nest at any depth and stay itself. A card in a sidebar and a card on the page are the same markup; the type inside each scales to its card. The same structure holds at every scale of context.

Changing variables instead of markup also keeps the layers from fighting. A product sets knobs on `:root`, and variants and contexts set a primitive's own variables, so a product never overrides a variant by accident (R13, R14, R15).

## How it is computed, in plain words

**Type answers to its container.** A role's size is a straight line between its two ends along the container's width, `100cqi` in CSS ([S2](S2.md)). A `.card`, a `.prose` column, a `.context` and the shell's grid are containers, so text inside them is sized from them.

**Layouts answer to their container.** Their breakpoints are container queries, written in rem:

- `.split` becomes one column under 36rem of container.
- `.section.cc-split` puts its head beside its body when the container is wider than 54rem.
- `.shell` has a tab bar when its box is under 48rem, and puts the aside under main under 72rem.

Because the breakpoints are in rem, a layout reflows when the reader's text grows, even after the cell has stopped at its cap ([S1](S1.md), R19).

**A context sets variables.** `.cc-dense .card { --card-pad: u }` makes every card inside a dense region tighter without a new class on the card. `.cc-on-media` does the same for things on a photograph.

**Who sets what.**
- The reader sets the dial and the text size.
- A product layer sets knobs on `:root`, and nothing else.
- Variants (`.cc-*`) and contexts set a primitive's own variables.
- Inline styles set variables only.

## Where it lives in the code

- `core.css`: `container-type: inline-size` on the card, prose, the shell grid and `.context`; the `@container` rules for `.split`, `.cc-split`, the shell and prose galleries; the contexts `.cc-dense` and `.cc-on-media`.
- `product.template.css`: every knob a product may set.
- Tests: `tests/contract.js` fails a product layer that sets anything but variables on `:root`. `tests/layout.js` checks that the same shell markup is a column in a wide box and a tab bar in a narrow one, in the same window.
