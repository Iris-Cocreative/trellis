# S5 Lines are planes

## What it is

A line can't be infinitely thin. It occupies pixels, and by rule it occupies the pixels just after its coordinate: to the right of it, and below it. So N cells drawn with their edges need N cells plus one line.

Two lines exist. `--line` is one logical pixel, which is 3 device pixels on an iPhone. `--hair` is one device pixel, the thinnest mark a screen can make: ⅓px on a 3× screen, ½px on 2×. Neither scales with the cell.

## Why

Without a rule for which pixels a line takes, a card's edge and the grid line it stands on land on different device pixels, and equal gaps draw unequal. The rule gives every line one owner and one place.

Lines are counted in device pixels and space in cells. A fitted cell is fractional; a line never is.

## How it is computed, in plain words

- A hair is 1 ÷ the device pixel ratio. The fitted width is the screen minus one hair, so the last line has its pixel ([S3](S3.md)).
- A card draws its edge as an `::after` frame one line larger than the box: inside the box on the left and top, and just outside it on the right and bottom. So each edge lies on its grid line's pixels, and the card's size never changes (R3).
- A box centered on a line is even: 14 = 12 + a line, or 18 = 12 + a quarter cell on each side (R1).
- Grids are drawn in device pixels, on a canvas. Repeating CSS gradients are not used, because Safari rounds each tile and the error grows across the screen (R4).
- WebKit, the engine of every iPhone browser, draws each box edge at the device pixel its coordinate rounds to, half up. The specimen's grid canvas uses the same rounding, so a card's edge and its grid line are the same physical pixel. Chrome's device emulation snaps to whole CSS pixels instead, so this can only be checked in WebKit.
- Rounding the fitted cell to 1/32 of a pixel keeps every half cell exact in the browser's 1/64-pixel layout grid. The cells fall short of the screen by up to about a pixel, split between the two edges.

## Where it lives in the code

- `core.css`: `--line`, `--dpr` and `--hair` in the tokens layer; the card's `::after` edge; controls with a fixed height keep a real border and give it back in their padding.
- `settle.js` writes the exact `--dpr`, since core only knows 2× and 3× and some phones are 2.625.
- `math.js`: `fit()` takes the hair from the pixel ratio.
- Tests: `tests/pixel.js` checks, in WebKit at 3×, that every card edge covers the same device pixels as the grid line it stands on, one CSS pixel (3 device pixels) wide.
